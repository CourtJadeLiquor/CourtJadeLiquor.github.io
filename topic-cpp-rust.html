C++17/20Rust性能

这个专题写什么

这一专题围绕“把系统写正确、写快、写得可维护”展开。C++ 与 Rust 是当前系统层的两种主要答案：前者靠约定与工具链纪律，后者把许多约定变成编译期检查。这里不做语言优劣的口号式对比，只记录具体问题下的具体做法。

写作计划

  • 现代 C++ 的显式设计：RAII、值语义、no-exceptions 下的 Status/Result 错误模型，以及为什么“显式”比“方便”更重要。
  • Rust 所有权与借用：move、借用检查与生命周期在实际数据结构中如何影响 API 形状；与 C++ 的智能指针对照。
  • FFI 与互操作：把 C++ 库包进 Rust 安全边界，或让 Rust 组件服务 C++ 主程序时的内存、异常与构建问题。
  • 性能剖析方法：perf、火焰图与微基准：先定位再优化，避免凭直觉重写热点。
  • SIMD 与并行：从可移植 SIMD、AVX2 到 OpenMP / oneTBB 的多版本内核组织方式。
  • 构建系统工程化：CMake 与 Cargo 的依赖管理、特性开关与多目标构建。
